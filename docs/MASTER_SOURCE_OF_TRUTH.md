# DN — MASTER SOURCE OF TRUTH

## Executive Summary

DN organizes Moments, activities, memories, greetings, original attachments and finance for Google accounts and browser-local guests. Published **1.0.35** provides compact automatically remembered filters, short comparison menus, explicit dropdown search focus and a minimal Dashboard greeting/header (CHG-105). This is the current product reference; rules are in [AGENTS.md](../AGENTS.md), commands in [README.md](../README.md), and execution/release evidence in the [change log](CHANGE_AUDIT_LOG.md).

## Release verification boundary

Version **1.0.35** is published from `OldVersion`, with all 63 served files, seven SPA routes and fresh Guest UI verified against the final tested production build. Validation and publication evidence belong to the newest completed change-log entry; a source version alone does not establish a Firebase release. The opt-in GitHub production workflow validates and publishes only an authorized `OldVersion` push marked `[deploy-live]` or manual dispatch, using the repository service-account secret. An authenticated local Hosting release can publish the already-tested build without a second version increment. Never conflate source publication with verified live Hosting.

## Product Overview

React/Vite, Router, Zustand, Firebase Auth/Firestore/Storage, Lucide and Framer Motion run without a separate API server. Formatted editing lazily loads the same Tiptap visual editor at every viewport width. Versions: [package.json](../package.json). Samples are isolated DEV-only fixtures without an account UID.

## Core Business Rules

- Preserve application IDs across links/reloads/backups. Numeric IDs become strings; missing account IDs use provider document IDs. Provider identity includes its collection; runtime routing metadata stays out of backups.
- Account, guest and sample scopes are separate. Matching loaded/active scope keys and Sample ownership gate cached data; stale load completions are ignored. An unavailable isolated fixture fails closed instead of falling through to real Guest writes. Samples take precedence only when explicitly active in development.
- Count each financial ID once within its kind: typed ledger first, unified legacy transactions second, nested activity expenses last. Preserve the first record's values and retain known account document sources for safe mutation. Income never creates an expense mirror.
- Finance totals follow recorded transaction-date conditions alone, independent of search/type/category/amount conditions: Income and Expense sum finite amounts; Balance = Income minus Expense. History defaults to newest first; Date, Amount or Title and direction can be selected without changing totals. Calculations use JavaScript Number; major totals display INR without fractional digits. Currency preferences do not convert values.
- Transactions require title/category/date and finite amount greater than zero. Activity belongs to its selected Moment; changing Moment clears Activity. Archived Moments remain selectable; saving rejects unavailable links.
- Moment status precedence is archived, explicitly cancelled, completed when all non-cancelled activities are complete and at least one exists, then in-progress. No activities/only cancelled activities means in-progress. Archive keeps children and finance records; normalization preserves an explicit cancelled status underneath the archived display state, so Restore does not reopen cancelled Moments. Older records whose cancellation was already overwritten cannot have that missing intent inferred.
- Dashboard Upcoming includes dates today through 30 calendar days. Archived/cancelled Moments are excluded from both Moment and Activity views; completed future Moments remain eligible. Each Moment type independently controls Show Moments on Dashboard (`showInDashboardUpcoming`, with legacy `showInDashboard` support) and Show Activities on Dashboard (`showActivitiesOnDashboard`). Missing/unknown flags default visible, including Activities on older types whose Moment flag is off. Moment and Activity lists honor their respective flags. Other uses matching custom-type metadata, otherwise generic Other metadata. Global Dashboard section Show/Hide choices remain separate.
- Recurrence projects monthly/yearly occurrences after the original start date; it creates no transactions or scheduled reminders. Local calendar parsing accepts legacy dates/Timestamps; short-month/leap-date projections retain JavaScript rollover behavior.

## Architecture Overview

`page → Zustand action / transaction coordinator → service → Firestore or guest localStorage`. `useAppStore` owns session/preferences/Code Lists; event/income/expense stores own records and scoped loads. Component state holds drafts and filters. Account CRUD is generally optimistic with targeted rollback. Reads use `getDocs` and cache per scope; there are no `onSnapshot` subscriptions, configured persistent Firestore cache, durable outbox or cross-device conflict engine.

Google popup sign-in hydrates Code Lists, attempts guest merge and activates the user with revision guards. Protected routes wait for auth, then allow account/guest access or redirect to login. Code Lists use transaction hydration, merged `setDoc` saves and owner/revision guards.

Firebase client configuration is embedded in [config](../src/firebase/config.js), not `VITE_FIREBASE_*`. [.firebaserc](../.firebaserc) selects `expense-tracker-divin`; [Hosting](../firebase.json) serves `dist` on site `dn-10` and rewrites SPA URLs. Production version 1.0.35 is published and its 63 served files and seven SPA responses were verified against the final build in CHG-105. No-cache headers match explicit `index.html`, worker, manifest and JS/CSS paths. Optional production Analytics failures do not block the app. All new original files save to scoped IndexedDB before their attachment metadata is saved. Signed-in Moment records sync the filename, content hash, type/size/timestamps and Activity relationship; file bytes never upload to Firebase Storage or Firestore. This is the intended Account policy, not a failed-upload fallback. Reads first check the scoped local original, including restored originals whose existing metadata retains a legacy cloud marker. Only missing-local reads of pre-existing `storage: firebase` references initialize Firebase Storage for compatibility; no metadata is rewritten by reading. No cloud upload queue, new collection or automatic file migration is introduced.

[Vite](../vite.config.js) injects version/timestamp/environment with deployment overrides. Production registers a versioned shell worker: navigation falls back to cached index, core assets are precached and visited `/assets/` JS/CSS/SVG/WOFF/WOFF2 files cache on demand. Activation removes old caches; Refresh handles waiting workers/reload. Development has no worker. Manifest installation is browser-provided; connectivity tracks browser network status. Shell caching does not synchronize Firebase data.

Build commands are in README and governance in AGENTS. Opt-in previews use the same Firebase backend.

## Data Model

| Domain | Account storage | Guest/browser storage |
|---|---|---|
| Moments, activities, memories, attachment metadata, greeting | `users/{uid}/eventGroups` aggregate documents | `dn_guest_eventGroups`; local copy in `dn_session_backup` |
| Original attachment files | Browser IndexedDB `dn_attachment_originals`, keyed by account UID and SHA-256; cloud stores reference metadata only | Same IndexedDB with separate Guest/Sample scopes |
| Standalone income/expense | `users/{uid}/incomes`, `users/{uid}/expenses` | `dn_guest_incomes`, `dn_guest_expenses` |
| Unified legacy finance | `users/{uid}/transactions`, selected by `kind` | No account-to-guest mirroring |
| Code Lists | `users/{uid}/settings/codelists` | `dn_guest_admin_values` plus schema version; legacy hydration keys supported |
| Preferences/theme | Browser-local even for accounts | `dn_preferences`, `dn_theme_choice` |
| Picker/filter/cover state | Browser-local, scoped | Favorite/recent Moment IDs by UID/guest; `dn_list_state_*` localStorage keeps list search/filter/sort and Quick Create type by account/guest, with activity choices per Moment; Activity cover selection and per-photo position/zoom are local UI choices |

Children are nested arrays with stable IDs and `eventId`/`activityId` financial links. New attachments accept files from 1 byte through 10 MB. Original bytes are stored once per scope using their SHA-256 content hash; parent Moment attachments keep `assetId`, `storage`, name/type/size/timestamps and optional `activityId`. Linking an attachment to an activity reuses that original. New Account references require a successful local save; local storage failures create no attachment record. Reads verify content integrity. Account metadata can appear on other devices, but originals stay in the saving browser until a backup is restored there. Clearing browser site storage can remove originals; filenames alone cannot recover them. Legacy metadata-only records cannot recover originals; supported pre-existing HTTPS image URLs may still display. Activity previews, the Moment's Attachments section and full preview/download use the same original, loaded near the viewport with object URLs released when no longer needed.

Moment reads fall back to `users/{uid}/events` only when `eventGroups` is empty. All-legacy accounts keep that destination for creation/restore; mutations use the source collection. Mixed accounts use `eventGroups`. Finance reads typed/unified records plus nested expenses. Optional legacy permission denial warns; other read errors propagate. Reads do not migrate/delete records or import browser-only IndexedDB data.

Runtime `firestoreId`/`firestoreCollection`/`firestoreSources` route account mutations. Financial sources are restricted to the expected typed collection or `transactions`; duplicate-copy updates/deletes use a batch and retain legacy kind/category fields. New finance uses typed collections regardless of imported metadata. Guest expense writes persist only the standalone ledger.

[Browser migration](../src/utils/storageMigration.js) copies old keys only to absent DN keys and keeps originals. Clear Local Data removes recognized keys of both generations, list-state memory and legacy transaction session filters, then reloads; it does not remove cloud/auth data, worker caches or IndexedDB originals. Removing attachment references likewise retains unreferenced originals in IndexedDB/Storage; automatic file deletion/garbage collection is not implemented. Old scoped transaction filters migrate to list memory. Unowned legacy global sort preferences are not assigned to an account; scoped sort starts at its default once on upgrade.

## Key Workflows

1. **Session/merge:** Login returns to the requested pathname, default Dashboard, without its query/hash. Guest entry restores local records/settings; logout keeps records. Account initialization exports Guest originals and copies them into this browser's destination-account scope before batching guest events/finance with fresh provider IDs and stable application IDs. Guest originals and records remain on local file-save or record-transfer failure. Auth/guest-snapshot guards stop further merge work after a scope or guest-record change. Both generations of guest record/mode keys clear only after the batch commits; original file objects remain retained. Merge failure is logged and sign-in proceeds.
2. **Create/edit:** Quick Create opens Moment/Activity/Transaction forms. Activity filters Moments by a remembered type, keeps archived/historical choices and clears excluded Moment selections. Workspace consumes `create=activity`; universal + Transaction presets the current Moment, and additionally the Activity/date on Activity Detail. Its form stays on the current route through save/cancel/error, guards duplicate submission and obsolete scopes, and restores focus to the persistent + control. Existing transaction editing/link changes/deletion stay on main Finance. Finance still supports `create=income|expense|transaction` plus optional `event`/`activity` presets. Settings hashes open matching sections.
3. **Finance:** Same-kind edits update source documents/rebuild mirrors; nested-only expenses update their aggregate. Kind conversion creates a typed replacement, reconciles mirrors and removes original documents, attempting compensation on failure. Persisted account expenses remain deletable with unavailable links; guest/nested-only activity links require a parent. Moment/activity deletion does not cascade into standalone finance.
4. **Backup:** Fresh source reads export JSON v3: Moments, flattened children, finance, Code Lists/version, preferences/settings, picker IDs and optional account metadata, plus optional `attachmentFiles` containing deduplicated base64 originals, content hash, type and byte size. Referenced originals must be readable and pass SHA-256 verification; a missing/corrupt original fails export. New exports include every asset reference's original; old metadata-only v3 remains accepted without `attachmentFiles`. Routing fields, auth credentials, rules, caches and scoped list-state memory are excluded; JSON is unencrypted. Export refuses a complete JSON over 50 MB rather than downloading a partial backup; import uses the same cap. Formatted note strings round-trip unchanged. IDs normalize and nested-only expenses appear once. V2 envelopes upgrade; unversioned input is settings-only; unsupported versions reject.
5. **Restore:** Validate envelope/date, six record arrays, configuration, unique IDs, child-to-Moment references and strict original-file shapes/base64/size/hash references; finance checks remain partial warnings. Confirmation targets the active account/guest. Original bytes pass size/hash checks and are stored in that destination before any record writes; session guards stop subsequent writes after scope changes. Existing values win; missing children append. New mirrors use destination values with matching links or skip stale reattachment. Guest restore preserves raw standalone masters independently of mirrors; corrupt ledgers block writes and nested-only projections stay nested. Sequential record writes precede configuration/reload; partial results remain and retries skip existing IDs. Samples block restore. Older metadata-only attachments require reattaching original files; the backup cannot recreate missing bytes.
6. **Settings:** Remote Code Lists, including empty lists, override browser values; missing settings seed guest/legacy values or defaults. Reset preserves business records/referenced custom values inactive. Clear Local Data is separately confirmed, with Data Model's scope. Reminder preferences do not establish delivery.

## Known Limitations

- All records and filter value suggestions remain in browser memory. Dropdown options are virtualized; full business-record lists are not windowed or server-paginated. The 50,000-record engine check is a local calculation measurement, not a browser, cloud or unlimited-dataset guarantee.

- Activity and finance mirror writes share a per-Moment queue within this client; other whole-Moment writers or another device can still overwrite concurrent edits. Scoped loads are not a complete cross-device conflict solution. Financial ledger/mirror reconciliation and restore span separate operations; compensation can fail. Batches synchronize duplicate financial copies, not the entire workflow.
- Guest merge is not deduplicated/chunked; limits/retries can fail or duplicate imports. Guest storage failures lack universal recovery.
- Code List usage counts depend on currently loaded stores; zero usage is not a server guarantee. The separate Settings Code List save handler does not await remote completion before success feedback.
- Backup checks do not prove every expense belongs to its stated Moment/activity; orphans can remain. Original-file backup/recovery is implemented for stored originals within the file/JSON limits, but comprehensive automatic backups and server-delivered reminders are not implemented. Unreferenced original files are retained without automatic cleanup.
- Cover selection/position/zoom and list order preferences stay in this browser and are excluded from recovery backups; original files/records keep the existing backup format. Native cover dragging/pinch and installed-PWA viewport behavior still need device validation.
- New attachment saves, backup restores and Guest sign-in transfers use browser-local originals for Account, Guest and Sample. No paid Storage plan is required by these new-file paths. Filenames/reference metadata sync for accounts; originals do not sync between devices. Browser quota, site-data removal or device loss can make files unavailable without a complete backup. Existing cloud-reference read compatibility remains subject to the previously observed unprovisioned Storage/billing setup (CHG-090); existing references/files are not migrated or deleted. Real signed-in cloud record writes, native/PWA durability, cross-user security and cross-device recovery remain unverified.
- Existing album export handlers produce printable HTML or HTML named `.doc`, not native PDF/DOCX; handler existence does not prove a reachable export flow. Inconsistent HTML escaping in those handlers remains a review gap. Offline shell caching does not guarantee unvisited pages/account data.
- Visual editing supports the existing note vocabulary, not arbitrary Word layouts, nested lists or rich clipboard formatting. Newly typed literal Markdown-like markers can change appearance after reload; backticks inside code are ambiguous in the existing grammar. Mobile keyboard positioning has a screenshot-guided correction with reduced-viewport and geometry tests; native iPhone/PWA caret behaviour still needs device confirmation.
- Root and rewritten deep-link HTML responses advertise `max-age=3600`, unlike explicit `/index.html`. Cached clients may need About → Refresh app to apply a release; worker caching and HTTP caching are separate.
